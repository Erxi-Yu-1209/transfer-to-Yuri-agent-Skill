# Authored rebuilds and inherited presentation

The exact-span adapter handles local changes. `rebuild-card` handles explicitly authored new openings and field rewrites after adapter inspection/extraction. It reads an original JSON/PNG card, a Markdown/JSON draft and a hash-bound field plan. The agent writes all prose and records; no model API is embedded.

The original card is the base, so extensions, regex objects, depth prompts, talkativeness, unknown fields and untouched worldbook activation settings survive. Markdown remains a source for chosen prose fields; its serializer-generated empty `extensions` never replaces inherited data. The MIT exporter is unchanged.

Use `presentation-audit` to inventory HTML/status candidates and image references. Then author a plan under `shared/assets/card-rebuild.schema.json`, `bind-rebuild`, and `rebuild-card`. `expected_value_sha256` hashes canonical JSON (`json.dumps(value, ensure_ascii=False, sort_keys=True, separators=(",", ":"))`). Use null as the preimage for a new allowed field. `draft_pointer` selects authored prose from the generated draft card. New greetings are authored by the agent, not generated by the build command.

Keep mode checks inherited markup/code and template tokens. Redesign needs the user's recorded instruction. Whole-worldbook replacement also needs explicit structure authorization; ordinary entry-content edits retain activation metadata. Source/draft hashes and non-overlapping field preimages protect against stale plans. These checks cannot prove literary quality or that a status protocol matches its regex; inspect that connection and use small fixtures in the actual JS dialect.

After conversion ask whether to keep styling or redesign it, and whether images should remain or be reconsidered. Use actual visual evidence; inventory alone is not visual inspection. Do not install image tools in this release. Keep semantic review, packaged JSON/PNG hashes, previews and actual host observations separate.
