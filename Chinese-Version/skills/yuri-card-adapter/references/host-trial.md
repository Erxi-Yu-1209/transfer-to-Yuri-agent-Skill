# Source diagnostics and host evidence

Before a trial, inspect author-supplied card and preset layers separately. Do not infer host behavior from a preset flag without a real delivered-context observation. Treat labels, placeholders and status strings as source text unless a documented parser or observed host assembly establishes otherwise.

## Source checks

- Check empty, duplicated or broken system-prompt stubs, unfilled placeholders and object-replacement characters. Record pointers; do not invent names or repair text outside the adaptation scope.
- Distinguish prose embedded in description from structured worldbook entries. An empty worldbook is not an import error by itself. Extracting entries changes activation, ordering and delivery and needs a separate plan.
- Distinguish known host macros, ordinary prose conventions and custom runtime protocols. A counter-like string is not automatically a macro. Never replace it with guessed host syntax or imply it will increment.
- Check capacity/census, chronology, alternate openings and player role. An unresolved source capacity question does not authorize adding a bed or changing the player identity.
- Compare card and supplied preset mandates, including status panels and formatting. Mark a conflict even if no field is edited; a model must still receive and resolve the instruction stack.
- Plain source prose may render plainly. Adding HTML, regex, UI or a status renderer is an optional authoring feature, not necessary evidence of successful genre conversion.

## Trial record

Use one row per observation with candidate_sha256, action, evidence_kind, observer, environment, result, failure_layer and short evidence/pointers. evidence_kind must identify actual_user_observation, actual_host_import, actual_live_model_roleplay, agent_simulation, or offline_check. Mark unavailable metadata unknown. A simulated model identifier or emulated prompt assembly does not verify the named service or current host implementation.

Keep author_review separate from author_acceptance_for_trial and final_acceptance. Record source-preserved issues, adaptation defects, import/rendering, prompt delivery and model portrayal separately. Include selected greeting, active entries, preset and model version when actually known. Run cooperation, conflict/open choice and cue-present/cue-recovery scenes when relevant. Do not fabricate a transcript to fill missing real-world evidence.

Use concise decision summaries and short sanitized excerpts, never hidden chain-of-thought. Keep actual feedback and long transcripts in an ignored private directory. Changing candidate bytes invalidates the old artifact binding; a new candidate needs new review and observations.
